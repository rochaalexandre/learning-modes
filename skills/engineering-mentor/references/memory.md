# Learning memory

## Initialize

Use `~/.software-engineering-mentor/` across repositories and agents. Create `archive/` and copy each missing file from this skill's [profile template](../assets/learning-profile.md) and [progress template](../assets/progress.md). Preserve every existing personalized file. Installation normally performs this initialization; use these steps if the skill was installed manually. Never commit, publish, or copy personal memory into a project. If a write is unavailable, say what was not saved and continue without a project-local substitute.

If `~/.learning-modes/progress.md` exists, preserve it. The installer copies it once into the new archive as migration history. When initializing manually, copy it to `archive/legacy-learning-modes.md` only if that file is absent, before starting the new active file. Reuse an existing migrated archive rather than copying it again on each initialization. Historical categories and assessments remain history; they do not silently expand the new active focus.

## Maintain active progress

Engineering Mentor primarily records observed learning evidence. Study Planner consults it to revise priorities when requested and updates goals when the learner explicitly changes the plan. Both use this same file; reread it before writing so another session's updates are retained.

Read the current file before editing. Record meaningful learner behavior: a decision explained, a plan revised from evidence, independent application, or a recurring difficulty. Include the date, project or context, concrete observation, and support supplied. Treat self-assessments as self-reports and distinguish them from observed evidence. Agent-written explanations and implementations are not evidence of learner capability; requesting implementation is not evidence of weakness.

Consolidate by the current focus instead of appending a session log. Keep at most three representative evidence bullets per focus and one current difficulty and next need. Keep the whole file within 120 lines; merge repetitive observations while retaining distinct evidence and uncertainty. If the learner chooses many focus areas, propose a narrower active set rather than silently dropping a goal. Record no invented baseline, score, or mastery label. Update without approval for each ordinary evidence change, and mention a material update briefly at a natural pause.

Use the initial focus in the template until the learner chooses another. New topics may supply evidence for those goals without becoming new goals. Completing a topic or exercise leaves the current cycle active. An ongoing obstacle calls for a different teaching approach and a concrete next need, not an automatic reset.

## Change focus or start a fresh cycle

Archive only when the learner explicitly changes learning focus or requests a fresh cycle. A passing interest in a topic is not a focus change. If the intended new focus is unclear, clarify it before resetting.

1. Copy the complete current `progress.md` into a unique dated file under `archive/` (add a suffix if needed). Verify the saved copy matches before replacing active progress. If archiving fails, leave active progress intact.
2. Initialize active progress for the requested focus. Retain relevant dated evidence for continuing competencies unless the learner requests a fresh assessment; mark new competencies as unassessed. Record the cycle date and reason. Completed or paused cycles remain in the archive without a mastery claim.
3. Preserve `learning-profile.md`. Confirm which focus is active and that the previous cycle was archived; archiving does not imply mastery.

For a historical question or a relevant new goal, inspect archive filenames first and read only pertinent cycles. Keep historical evidence attributed to its date and context. Bring forward only a concise relevant observation, not the entire history.

## Personalize the profile

Update the profile when the learner explicitly states a durable preference or asks to change it. Describe tentative observations as hypotheses in progress until confirmed. Keep preferences separate from capability evidence and temporary task instructions. Installation and cycle resets preserve the profile.
