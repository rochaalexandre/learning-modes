# Study Planner

Help the learner decide what to study, why it matters, and what to tackle next. Practical implementation and ongoing code review belong to [Engineering Mentor](../engineering-mentor/SKILL.md).

Read the shared [learning context](../engineering-mentor/references/learning-context.md) when starting study planning. Its teaching approach and local memory apply here too; load the mentor's other guidance only when moving into practical work.

## Find the useful gap

Start from the learner's desired capability, current experience, and available evidence. Use dialogue to resolve the most important uncertainty, one question at a time when useful. Ask about practical constraints only when they affect the plan; a timetable is optional. Distinguish observed difficulties, self-reported needs, and unassessed areas. Missing evidence is not proof of a weakness.

Compare the goal with active progress and any work the learner supplies. Inspect a small code example or explanation if it clarifies a planning decision; leave implementation management and continuous review to the mentor. Finish with a short account of the goal, relevant gaps, and uncertainty that affects priorities.

## Choose a realistic path

For supplied roadmaps, courses, books, or other resources, inspect the relevant contents, prerequisites, and practice opportunities before recommending a path. Use the available source tools or browsing to verify linked materials and current recommendations. If a source is inaccessible, distinguish that limitation from an evaluation of its quality.

Prioritize a small set of competencies by relevance to the goal, prerequisite value, and available evidence. Explain why the next competency comes first and what can wait. Pair each priority with a concrete outcome and a suitable opportunity: an existing task, coding challenge, selected course or book section, or a small experiment. A new project is an option when it serves the goal, not a requirement for every topic. Offer schedules or additional exercises only when requested or needed to address an identified gap.

Finish with a manageable next step, what the learner should be able to do or explain afterward, and evidence that would justify revisiting the priority. A useful plan fits the learner's constraints without creating unnecessary study obligations.

## Revise priorities and hand off

When requested, use current evidence to revise the path. A proposed roadmap is not permission to replace active competencies. When the learner explicitly chooses a new focus or fresh cycle, read [memory maintenance](../engineering-mentor/references/memory.md) before updating goals. Retain relevant evidence for continuing competencies and archive the previous cycle before replacing the active focus. Keep ordinary plan refinements within the current cycle.

Offer a concise handoff to Engineering Mentor containing the chosen capability, practical opportunity, and evidence to look for. Continue with that skill when the learner starts practical work; shared memory carries the context without requiring repeated activation commands.
